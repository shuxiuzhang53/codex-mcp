# Codex + Paper Search MCP + Zotero MCP 首次运行清单

已完成：

- Codex CLI 可用：`codex-cli 0.125.0`
- `uvx` 可用：`uvx 0.11.7`
- 已生成可执行启动器：`~/codex-mcp/codex-literature.sh`
- 已生成私有环境变量文件：`~/codex-mcp/mcp-literature.env`
- 已新增 readiness 自检脚本：`~/codex-mcp/check-literature-mcp-ready.sh`
- 已验证 runtime MCP 注入可被 Codex 识别：
  - `paper_search`
  - `zotero`
- 已切换为 Zotero Web API 模式：`ZOTERO_LOCAL=false`。这是当前 WSL/Codex sandbox 下更稳的路线。
- Zotero Web API 凭据已经写入本地私密 env 文件。
- `paper-search-mcp` 已安装到 `~/codex-mcp/.venv-paper-search`。
- `zotero-mcp` 已安装为本地命令，并且 wrapper 会优先使用本地命令。
- 本地 MCP 启动层已经通过，可进入 3 篇论文端到端测试前置状态。

当前阻塞：

- `~/.codex/config.toml` 所在挂载是只读，无法永久追加配置。
- 当前网络 DNS 失败，不能访问 `api.zotero.org`、arXiv/Crossref/OpenAlex/Semantic Scholar 等外部 API；真实论文检索和 Zotero Web API 导入需要在有外网 DNS 的环境中运行。现在 readiness 会把这类外部 API 不可达标记为 `BLOCKED`，防止误跑导入测试。
- 没有检测到本机 Zotero 桌面端；如果只用 Zotero Web API，可以先不装桌面端。

## 推荐路线

先走 Web API 路线，目标是跑通：

```text
搜索论文 -> 筛选 3 篇 -> 创建 Zotero 测试 collection -> 通过 DOI/URL 导入 -> 附加开放 PDF -> 输出表格
```

本地 Zotero 桌面端、语义搜索、全文索引可以第二阶段再加。

## 1. 确认 Zotero Web API 配置

当前已经配置好 Web API 凭据。后续如果要更换 API Key，打开：

```text
https://www.zotero.org/settings/keys
```

然后在本机终端运行，不要把 key 发到聊天：

```bash
~/codex-mcp/set-zotero-web-api-env.sh
```

它会让你输入：

- Zotero library id/user id，个人库需要 Zotero 页面显示的数字 User ID，不是用户名
- library type，个人库填 `user`
- Unpaywall/contact email
- 新 Zotero API key，输入时不会显示

## 1b. 备用：启用 Zotero 本地 API

如果后续要回到本地模式：

1. 打开 Zotero。
2. 进入 Settings/Preferences -> Advanced -> API。
3. 勾选 `Allow other applications on this computer to communicate with Zotero`。
4. 设置 `ZOTERO_LOCAL="true"`。

但当前 WSL/Codex sandbox 访问 Windows localhost 不稳定，优先 Web API。

## 1c. Zotero Web API 凭据来源

打开 Zotero API Key 页面：

```text
https://www.zotero.org/settings/keys
```

创建一个测试用 Key，建议先只给个人 library 的读写权限。

然后编辑：

```bash
~/codex-mcp/mcp-literature.env
```

至少需要：

```bash
ZOTERO_API_KEY="你的 Zotero API Key"
ZOTERO_LIBRARY_ID="你的 Zotero User ID"
ZOTERO_LIBRARY_TYPE="user"
UNPAYWALL_EMAIL="你的邮箱"
PAPER_SEARCH_MCP_UNPAYWALL_EMAIL="你的邮箱"
```

## 2. 网络恢复后安装 MCP 工具

当前 MCP 工具已经本地安装完成。只有重装或升级时才需要执行本节。

```bash
~/codex-mcp/install-literature-mcp-tools.sh
```

如果连接 PyPI 超时，使用镜像重试：

```bash
CODEX_LITERATURE_UV_INDEX=https://pypi.tuna.tsinghua.edu.cn/simple ~/codex-mcp/install-literature-mcp-tools.sh
```

日常验证直接运行：

```bash
~/codex-mcp/check-literature-mcp-ready.sh
~/codex-mcp/verify-literature-mcp.sh
```

看到 `verify-literature-mcp.sh` 输出 `paper_search_import_ok` 和 `zotero-mcp` 的 help，就说明本地 server 程序可启动。

看到 readiness 自检输出 `OK: Ready for the 3-paper end-to-end Zotero import test`，才说明外部 API 也可达，可以跑真实 3 篇导入测试。

说明：`paper-search-mcp` 当前 PyPI 包可能没有 `uv tool install` 可用的命令入口，所以安装脚本会把它装进 `~/codex-mcp/.venv-paper-search`，并通过 `python -m paper_search_mcp.server` 启动。

## 3. 启动带 MCP 的 Codex

因为当前 `~/.codex/config.toml` 只读，先用 runtime launcher：

```bash
~/codex-mcp/codex-literature.sh
```

确认 MCP 列表：

```bash
~/codex-mcp/codex-literature.sh mcp list
```

应该能看到：

```text
paper_search
zotero
```

正式进入交互前先运行：

```bash
~/codex-mcp/check-literature-mcp-ready.sh
```

如果它仍提示 `BLOCKED`，先处理输出里的失败项；否则启动器会阻止完整 Codex 会话，避免进入后才发现不能导入。

只想离线检查 MCP 注册时，可以运行：

```bash
~/codex-mcp/codex-literature.sh mcp list
```

只想离线打开 Codex 检查 MCP 交互、不做论文检索或 Zotero 导入时，可以显式跳过外部 API gate：

```bash
CODEX_LITERATURE_ALLOW_OFFLINE=1 ~/codex-mcp/codex-literature.sh
```

如果你是在 Windows 上运行 Zotero、在 WSL2 里运行 Codex，`localhost` 可能不是同一个网络命名空间。此时在 Windows PowerShell 里测试：

```powershell
curl.exe -i http://localhost:23119/api/
```

如果 PowerShell 能通但 WSL/Codex 不能通，说明是 WSL/沙箱网络隔离；可以改走 Zotero Web API Key 路线，或把 Codex 放到能访问 Windows localhost 的环境里运行。

## 4. 第一次端到端测试提示词

在 `~/codex-mcp/codex-literature.sh` 启动的 Codex 中输入：

```text
检索 2023 年以来 retrieval augmented generation 的开放获取论文，先只选 3 篇。
要求：
1. 优先 arXiv、Semantic Scholar、OpenAlex、Crossref；
2. 去重；
3. 创建 Zotero collection：Codex MCP Test - RAG；
4. 能通过 DOI 或 arXiv URL 导入的导入 Zotero；
5. 能找到开放获取 PDF 的附加 PDF；
6. 每篇添加 tags：codex-mcp-test, RAG；
7. 最后输出表格：标题、作者、年份、来源、DOI/arXiv、PDF 状态、Zotero 导入状态；
8. 不要导入超过 3 篇。
```

## 5. 正式批量导入提示词模板

```text
帮我检索【主题】在【年份范围】的高质量论文。
要求：
1. 优先开放获取；
2. 来源优先 arXiv、Semantic Scholar、OpenAlex、Crossref、PubMed/PMC；
3. 去重，并按相关性、年份、引用量排序；
4. 先输出候选清单，不要立即导入；
5. 我确认后，再创建 Zotero collection：【collection 名称】；
6. 导入最多【数量】篇；
7. 能找到开放 PDF 的附加 PDF；
8. 每篇添加 tags：【tag1】, 【tag2】, 【tag3】；
9. 最后输出：标题、作者、年份、venue、DOI/arXiv、为什么值得读、Zotero 导入状态。
```

## 6. 安全规则

- 第一次只导入 3 篇。
- 正式批量导入前，先让 Codex 输出候选清单。
- 不下载非开放获取 PDF。
- 不要把 `mcp-literature.env` 发给任何人，也不要提交到 git。
- 如果后续启用 Zotero 本地模式，再开启 Zotero 7 的 local API。
